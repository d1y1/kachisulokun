# イベント記録

特定日の告知・結果・考察。

- ファイル名: `YYYY-MM-DD-<店舗スラッグ>.md`
- テンプレ: `_template.md`
- X告知と翌日の差枚データを**必ず突合**して記録する
- 当日予想は翌日以降に「結果・的中判定」を追記する（`playbooks/x-event-analysis.md` セクション5）
- **日付から店を引くときは `calendar.md`（旧イベ日付カレンダー）を最初に見る**

## living（取材公約メモ）の鮮度ルール

日付固定ではない取材名の傾向は `種別: living` のファイルに置く（例: `win6game-s-grade-red.md`）。

| フィールド | 意味 |
|------------|------|
| `最終確認日` | ソースを取り直した日 |
| `鮮度期限日` | 原則 最終確認＋90日。過ぎたら**引用前に再取得必須** |
| `鮮度ステータス` | `有効` / `要更新` |

エージェント動作:

1. living を使う前に `鮮度期限日` を見る
2. 期限切れ、またはファイル内「即時失効」条件に当たる → Webで最新を取り、ファイルを更新してから使う
3. 古い記述を期限切れのまま断定引用しない

日次ファイル（`YYYY-MM-DD-...`）は履歴なので鮮度期限の対象外。傾向の最新版は living を見ること。
